  • Requisitos Inversos

Requisitos Funcionais (RF)

O que o sistema deve fazer:

  • O sistema deve permitir o login de alunos e professores via RA.

  • O sistema deve disponibilizar a leitura de livros digitais (e-books) em formato PDF/EPUB.

  • O sistema deve permitir a reserva de exemplares físicos.

  • O aluno deve conseguir visualizar o histórico de seus empréstimos ativos e passados.

  • O sistema deve enviar notificações sobre datas de devolução próximas.

  • O sistema deve permitir a solicitação de materiais complementares aos professores.

  • O sistema deve possuir uma barra de busca por título, autor ou gênero.

  • O sistema deve permitir que o bibliotecário cadastre novos exemplares no acervo.

Requisitos Não Funcionais (RNF)

Atributos de qualidade e restrições:

  • O sistema deve ser responsivo (funcionar em celulares e tablets).

  • O tempo de carregamento de um livro digital não deve ultrapassar 5 segundos.

  • A interface deve seguir as normas de acessibilidade (WCAG).

  • O sistema deve estar disponível 99% do tempo (alta disponibilidade).

  • As senhas dos usuários devem ser armazenadas com criptografia.

  • O sistema deve suportar até 500 acessos simultâneos sem perda de performance.

  • O design deve seguir a identidade visual da escola "Futuro do Saber".

  • O banco de dados deve realizar backups automáticos a cada 24 horas.

Requisitos Inversos (RI)

O que o sistema não deve fazer/permitir:

  • O sistema não deve permitir que um aluno reserve mais de 3 livros físicos simultaneamente.

  • O sistema não deve permitir a exclusão de registros de empréstimos pendentes.

  • O sistema não deve exibir dados pessoais de outros alunos para terceiros.

  • O sistema não deve permitir o acesso a livros com classificação indicativa superior à idade do aluno.

  • O sistema não deve permitir o download definitivo de arquivos protegidos por direitos autorais (apenas leitura online).
